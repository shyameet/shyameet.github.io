A note to my future self, because in four months I will have forgotten.

**Posting.** Open `/admin/` on the phone, pick a section, hit the big **Talk** button
and speak. It keeps listening through pauses — it does not cut out when I stop to
think — and the words land in the box as I go. Tap it again when I am done, then Publish. It commits a markdown file to the repo, the site rebuilds itself,
and it is live in under a minute. The draft saves to the phone as I speak, so a dropped
signal costs nothing.

**The sections** are fixed on purpose — if I have to invent a category every time, I will
stop posting by Thursday:

| | |
|---|---|
| **Day Tasks** | What has to happen today |
| **Week Tasks** | The week's list, re-read on Sunday |
| **Daily** | The schedule, and how the day actually went |
| **Goals** | Anything pointed at where I am trying to get |
| **Feynman** | Learn it by explaining it back in plain words |
| **Wins** | What went well, for a bad day |
| **Mistakes** | What went wrong, and what I will do instead |
| **Speaking** | Spoken sessions, thinking out loud |
| **Vocabulary** | Words and openers to actually use |
| **Blabber** | Everything else |

Two sections do something extra. **Mistakes** has a second field for the lesson, because
that is the part that stops it happening twice. The two **task** sections count their own
checkboxes — write `- [ ]` lines (the editor has a button) and the post shows how much of
it is done. **On my own phone I can tap those boxes straight on the page** to tick them
off; it rewrites the file and commits. Anyone else just sees a read-only list, because
the tapping only switches on when the editor's token is present in that browser.

**From the desk**, drop a `.md` file into `content/posts/`. Same thing. Obsidian can open
that folder as a vault. No database, no CMS — if GitHub vanished tomorrow the posts are
still a folder of markdown on my laptop.
